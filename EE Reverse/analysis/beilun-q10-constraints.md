## 约束（这才是画图的依据，不是 PNG 像素）

1. 抛物线**过原点** O(0,0)。
2. **最高点**是 N(n, 6√3)：顶点纵坐标 = 6√3 ≈ 10.3923。
3. 过 I(1.5, y1) 与 J(5.5, y2)；选项 D「y1=y2」⇒ 这两点等高 ⇒
   对称轴 x = (1.5+5.5)/2 = **3.5** ⇒ **n = 3.5**。
4. ⇒ 抛物线 `y = A·x·(7 − x)`，由顶点 6√3 = A·3.5·3.5 ⇒ A = 6√3/12.25 ≈ 0.8483。
   于是 y(1.5) = y(5.5) ≈ 6.998 ≈ 7，另一交点 x = 7。
   （C 说 "点(2, 9√3/2)"：9√3/2 ≈ 7.794 ≈ 6√3·0.75，**不在**该抛物线上 —— C 是干扰项。）

## ⚠️ 已画的那张图2（画布曾为 0xabe2838）是按【原图像素】描的，错在两处

| 项 | 我画的（照像素） | 应该是（按题干约束） |
|---|---|---|
| 顶点高度 | ≈ 2.0（raster 拟合 `row=0.031788col²−41.49col+13588.5`，顶点 row 50.19） | **6√3 ≈ 10.39**（与 x 轴同尺度） |
| 顶点标注 | `N(a,b,√3)` | **`N(n, 6√3)`** |

原因：**我违反了自己的铁律** —— 抛物线的"高度"是题干给定的数学量，我却去量了栅格像素的
纵横比（栅格是非等比缩放的），于是把 10.39 压缩成了 2.0。

## 正确的画法（重画时照这个来）

- 定尺度：**x 与 y 必须同尺度**（否则抛物线不是抛物线）。取 1 单位 = U canvas 单位，
  顶点 (3.5, 6√3) 与交点 (7,0) 决定整条曲线。
- `y = 6√3/12.25 · x · (7 − x)`，定义域取图上可见部分 x ∈ [0, 5.5]（图2 是"部分图象"）。
- 顶点 N(3.5, 6√3) **不再是"看起来最高"的地方**，而是真实顶点。
- 二次→三次升阶仍精确：两段三次贝塞尔在顶点处相接，共 7 个控制点。
- 标注：`O`、`x`、`y`、`N(n, 6√3)`、`图2`。

## 附带结论（本轮实测，已写入 AGENTS.md）

- `fontSheet` 必须取 `caretContext().fontSheet` == `pageLists()[].styleSheet`（页面表 `+0x38`）。
  传 `pageLists()[].ui`（`+0x40`）会 `access violation accessing 0x68`，
  并留下半成品对象 → 挂上画布后**下次重绘崩进程**。
- 废纸上**一次连建 11 个对象 + redrawAll()** 实测无害；批量不是崩溃原因。
